# 管理画面

`/admin/` で開く。編集した内容は `src/content/` のファイルに書き込まれる。

## メニュー

| 画面 | 編集できるもの |
|---|---|
| トップページ | KV・キャッチ・KV下の案内ボタン・フォトギャラリー・ゲスト・後援 |
| アバウト | 冒頭の文（トップにも出る）／続きの文／PRムービー |
| スケジュール | 開催日ごとのプログラム |
| コンテンツ | 上映作品・出演者・出店 |
| チケット | 料金・購入先・注意事項 |
| アクセス | 会場名・住所・地図・駐車場の案内・宿泊施設 |

協賛はトップページ画面の中で直接編集する（`type: "sub"` + `inline`）。
宿泊はアクセス画面に名前だけ並べ、押すと個別ページで編集する（`type: "sub"`）。
入力する項目が少ないものは前者、紹介文まであるものは後者。

編集画面の右には、その内容が実際にどう出るかのプレビューが並ぶ。
保存すると自動で更新される。

## 来年の開催回に切り替える

`src/content/event/2027.md` を作って `schedule` に日を並べ、
`current: true` を付ける（古い方の `current` は消す）。コンテンツの `day` は
新しい日のidに付け替える。ここは管理画面ではなくファイルで行う作業。

## 日付は1か所だけ書く

KVやチケットページに出る「2026.10.17 sat. - 10.18 sun.」は、
トップページの「開催日」に入れた日付から自動で組み立てる（`dateRangeLabel`）。
2日以上あるときは、後ろの日から重なる年を省く。

## 保存とサイトへの反映

- **自動では保存しない。** 保存するとすぐ公開サイトに出るので、書きかけが出ないようにしている。
  代わりに、保存していない変更があると下の帯に「保存していない変更があります」と出て、
  保存ボタンが縁取られる。そのままメニューなどで離れようとすると確認が出る
- ⌘S（Windows は Ctrl+S）でも保存できる
- 本番は保存するたびにサイトを作り直すので、**サイトに出るまで1〜2分かかる**。
  その間は「サイトに反映しています…」、プレビューには「反映待ち…」と出て、
  終わると自動でプレビューを読み直す
- 1回の保存（協賛の追加・削除も含めて）は1つのコミットにまとめる。
  中身の変わらないファイルは書かないので、何も変えずに保存してもサイトは作り直されない
- 開催回の1ファイルは複数の画面で分担しているので、各画面は**自分の担当の項目だけ**を書く。
  別のタブで開いていた古い画面から保存しても、ほかの画面の変更は戻らない
  （開催日は、日付をトップページ、見出しをスケジュール画面が受け持ち、日ごとに重ねる）

## ページごとに公開・非公開を切り替える

アバウト・スケジュール・コンテンツ・アクセスの4画面は、見出しのすぐ下に
**公開中／非公開** のスイッチがある。押した時点で保存される（「保存する」は要らない）。

非公開にすると：

- 一般の人には、そのページの代わりに **COMING SOON** が出る（URLはそのまま）
- ログインしていても、サイトを直接開けば COMING SOON が出る（一般の人と同じ見え方）。
  中身が見えるのは**管理画面の右のプレビューの中だけ**で、上に「非公開のページです」の帯が出る。
  そこで仕上がりを確かめてから公開できる
- トップページからも、そのページの中身とリンクを外す
  （アバウト → 冒頭の文とPRムービー、スケジュール → 各日の時間帯、コンテンツ → コンテンツと注目ムービーの欄）
- コンテンツが非公開のあいだは、スケジュールの表から個別ページへのリンクも外す
- そのページのSNS画像も一般には出さない
- 左のメニューに「非公開」の印が付く

グローバルナビのリンクは残す（押すと COMING SOON が出る）。
値は開催回のファイルの `hiddenPages` に入る。

## 写真の大きさは気にしなくてよい

上げた画像は置き場所ごとに決まった形へ自動でそろえる（`src/lib/admin/image.ts`）。

| 置き場所 | そろえ方 |
|---|---|
| コンテンツの画像 | 1280×720（16:9）に切り抜き・webp |
| フォトギャラリー | 1600×1200（4:3）に切り抜き・webp |
| 協賛ロゴ | 幅800pxまで・透過を残すのでPNG |
| KV | 形はそのまま、幅2400pxまで・webp |

切り抜きは中央ではなく、写真の中で目を引くところを残す。

## SNS画像を作る

「SNS画像ダウンロード」で、管理画面に入れた内容から Instagram用（1080×1350）の
PNGを作る。**内容を直せば画像も自動で変わる**ので、作り置きしなくてよい。

入口はまとまりのカード。押すとそのまとまりの画像が並び、1枚ずつでも
まとめて（zip）でも落とせる。入口のページからは全部まとめてだけ落とせる。

まとまりはメニューと同じ区切りにしてある。

| まとまり | 中身 |
|---|---|
| 概要 | KV・キャッチコピー・日付・会場 |
| アバウト | 冒頭の紹介文 |
| スケジュール | DAY 1 / DAY 2 …。入りきらない日は自動で2枚以上に分ける |
| コンテンツ | 1件ずつ。分類・画像・時刻・紹介文の書き出し |
| チケット | 料金表（名前が左、金額が右）と注意事項 |
| アクセス | 会場・住所・行き方と宿泊 |

画像の下の「キャプション」を開くと、**SNSに貼る文章の下書き**が出る。
管理画面に入っている内容から組み立てているので、直せば文章も変わる。
ハッシュタグは `src/config/site.ts` の `hashtags` で決める。

公開ページにも同じ画像を落とせるボタンを置いてある
（スケジュールの日ごと・コンテンツの個別ページ・チケット・アクセス）。
スマホでは共有シートが開くので、来場者がそのままSNSへ流せる。

画像は `/api/og/*.png` がその場で描いている（`src/lib/og/`）。
色は `theme.css` から読むので、別イベントに転用しても色が付いてくる。
フォントは Google Fonts から、その画像で使う文字だけを取ってくる。
一覧に出るのは小さく描いたもの（`?w=360`）で、保存は原寸。

## 急なお知らせを出す

トップページ画面の一番上「お知らせの帯」に文言を入れると、**全ページの一番上**に
帯が出る（アンケート、チケット発売、当日の中止連絡など）。
リンク先とボタンの文字を入れればボタンも付く。文言を空にすれば帯ごと消える。

## スケジュールの入力

1日ぶんを1本のリストとして編集する。画面でできるのは3つだけ。

- **見出しの追加・編集**（「第1部 ／ ムービー」など）
- **見出しの位置決め** … 左の ☰ を掴んで、置きたい場所へ動かす
- **ゲートオープンの時刻** … 各日の先頭に固定で入っている行

コンテンツで「開催日」と「開始時刻」を入れた項目は、**分類を問わず時刻順に自動で並ぶ**。
編集画面ではそれが薄い行として出る（読むだけ。直すのはコンテンツ画面）。

見出しから次の見出しの手前までが1つの「部」になる。
「第2部 ／ ムービー」の中にライブが入っていてもかまわない。部の名前は見出しであって、
中身を絞り込むものではない。

内部的には、見出しのすぐ下にある行の時刻を `startsAt` として持つ。
表示には出ない、置き場所を覚えておくためだけの値。
ゲートオープンは `extras` の1件目として持つ。

開催日（DAY 1 / DAY 2 …）は**増やしたり減らしたりできない**。
トップページの「開催日」で直せるのは日付と時間帯の文字だけ。
日そのものを増減すると、その日に紐づいたコンテンツが行き場を失うため、
開催回のファイル（`src/content/event/*.md`）を直接編集する作業にしてある。

## 開催回の1ファイルを3画面で分担している

トップページ・スケジュール・アクセスは、どれも `src/content/event/2026.md` を
編集している。保存のときは**既存の内容に上書きする形で合成**するので、
その画面が扱わない項目（例：トップページから保存したときのスケジュール）は消えない。

## 日と時刻を入れるだけでスケジュールに並ぶ

コンテンツで「開催日」と「開始時刻」を入れると、スケジュールのその日・その部に
時刻順で自動的に入る。スケジュール側に書き写す必要はない。

どの部に入るかは時刻で決まる。直前の見出しの部に入る。

## コンテンツと宿泊は同じフォルダ

どちらも `src/content/items/` に入っている。`group` が `stay` のものは
「コンテンツ」画面から外し（`CollectionDef.filter`）、**アクセス画面の下の枠**に
名前だけ並べる（`type: "sub"` の欄）。押すと個別ページで編集する。
並べ替えは ☰ で、その場で保存される。個別ページの「一覧へ戻る」は
アクセス画面へ戻る（`CollectionDef.backTo`）。

## 地図のURLは1つでよい

「地図のURL」だけ入れれば、埋め込みとリンクの両方をそこから組み立てる
（`mapLinks`）。URL の `q` / `query` から場所を取り出し、足りない方を作る。
住所を入れてある場合はそちらが優先。

## 分類によって出す欄が変わる

`Field.hideFor` にその分類を書くと、その分類を選んでいるあいだ欄が消える。
フードとショップ ＆ ブースに「動画」を出さないのはこれ。
公開側は `site.ts` の `video: false` で、動画があっても画像だけで見せる。

## 保存するとファイル内のコメントは消える

保存時にファイルを丸ごと書き直すため、`# ...` のコメントは残らない。
**開発用の覚え書きは md ではなく `docs/` に置くこと。**
差し替えが必要な仮データは `docs/DUMMY.md` にまとめてある。

## 環境変数

| 変数 | 用途 |
|---|---|
| `ADMIN_PASSWORD` | 管理画面のパスワード。**本番では必須** |
| `AUTH_SECRET` | クッキーの署名に使う任意の長い文字列 |
| `GITHUB_TOKEN` | 本番で保存するときに使う。リポジトリへの書き込み権限が要る |
| `GITHUB_REPO` | `owner/name` |
| `GITHUB_BRANCH` | 既定は `main` |
| `SITE_PASSWORD` | **公開前のパスワード**。入れるとサイト全体が隠れる |

ローカル開発では `ADMIN_PASSWORD` を設定しなければログインなしで入れる。
本番（Vercel）では保存内容を GitHub にコミットし、その push で再ビルドが走る。

## 公開前はパスワードで隠す

`SITE_PASSWORD` を入れると、サイトを開いたときにパスワードの入力画面（`/gate`）が出る。
入れるのはパスワードだけで、ユーザー名は無い。一度入れると30日は聞かれない。
関係者だけに見せたいあいだはこれを付けておく。**一般公開するときは
Vercel からこの変数を消すだけ**（消せばゲートは無くなる）。
