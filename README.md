# AREA UNITE / 汎用イベントサイト・テンプレート

スノーボード・アウトドア系のイベントサイトを想定した汎用テンプレート。
第1号の実装として AREA UNITE の内容を入れている。

**設計の前提**：このサイトはエリアユナイト専用のオリジナルデザインではなく、
**他のイベントにも使い回せるテンプレート**として作っている。
見出しやレイアウトに固有の癖をつけず、「見やすさ」と「差し替えやすさ」を優先する。

---

## 別のイベントに転用する手順

差し替えるのは次の3つだけ。ページやコンポーネントに手を入れる必要はない。

| # | ファイル | 変えるもの |
|---|---|---|
| 1 | `src/styles/theme.css` | ブランドカラー・背景・フォント・角丸（サイト全体の色が入れ替わる） |
| 2 | `src/config/site.ts` | イベント名・キャッチ・SNS・ナビ・一覧ページの種類（`groups`） |
| 3 | `public/images/kv/` + `src/content/` | KV画像と中身 |

### 1. 色を変える

`src/styles/theme.css` の `--brand` を変えるだけで、ボタン・見出しの罫・
時刻・リンクなど、アクセントが入るところがすべて追従する。
ライトテーマにしたい場合は `--bg` / `--surface` / `--text` を反転させる。

### 2. コンテンツの分類を増やす／減らす

グローバルナビは **ABOUT / TICKET / SCHEDULE / CONTENTS / ACCESS の5つに固定**し、
その下の分類は親ページの中のセクションとして持つ。ページを増やさずに項目を足せるので、
ナビが伸びていかない。

`src/config/site.ts` の `groups` に1件足すと、

- 親ページ（`/contents/` など）にセクションが1つ増える
- そのページ内タブに1つ増える
- グローバルナビの子メニュー（PCはホバー、スマホはドロワー）に1つ増える
- トップページ CONTENTS の導線カードに1枚増える

が全部まとめて起きる。減らすときは消すだけ。

```ts
workshop: {
  label: "Workshop",
  jp: "ワークショップ",
  lead: "当日開催する体験プログラム。",
  layout: "grid",       // grid = カード格子 / list = 時刻つきの1列
  ratio: "4 / 3",
  parent: "contents",   // contents か access
},
```

### 日をまたぐ開催での並び順

項目には日付を直接書かず、`day` に開催日のid（`day1` / `day2` …）を書く。

```yaml
day: day1
time: "17:30"
```

- 画面に出る日付は開催回の `schedule` の `note` から引く。
  日付が変わっても、直すのは開催回の1か所だけで全項目に反映される
- 一覧（CONTENTS）の並び順は管理画面で並べ替えた順（`order`）
- スケジュールには**その日のものだけ**が時刻順に並ぶ

つまり管理画面では「どの日か」を選んで時刻を入れるだけで、
スケジュールの正しい位置に並ぶ。`day` を書かない項目は
どの日にも出るので、1日開催なら省略してよい。

### スケジュールの持ち方

1日は「見出し」（`parts`）と「コンテンツに載せない行」（`extras`）だけを持つ。
その日のコンテンツは分類を問わず時刻順に自動で並び、見出しがその間に挟まる。

```yaml
parts:
  - label: 第2部 ／ ムービー
    startsAt: "17:30"          # ここから次の見出しの手前までが1つの部
extras:
  - time: "12:00"
    title: ゲートオープン       # コンテンツに登録しない行
```

上映作品を CONTENTS ページとスケジュールで**二重に持たずに済む**。
作品や時刻を直すときは `src/content/items/` 側だけを直せば両方に反映される。
ムービーは「制作者名」＋「作品名」の形で1行にまとめて表示する
（分類ごとの `scheduleFormat`）。同じ時刻が続く行では、時刻は最初の1行にだけ出る。

`startsAt` は見出しの置き場所を覚えておくための値で、画面には出ない。
管理画面では ☰ で見出しを動かすと、その位置から自動で入る。

SCHEDULE の子（DAY 1 / DAY 2 …）だけは設定ではなく開催回のデータから生える。
`src/content/event/*.md` の `schedule` に日を足すと、ページと子メニューが増える。
`time:` に `"12:00 - LATE"` のように書くとトップの要約に出る（省略時は
その日の最初と最後の時刻から自動で組み立てる）。

グローバルナビは、ヘッダー右のCTAボタンと同じ行き先の項目をバーから外す。
そのためチケットは「ボタン」としてだけ出る（CTAが隠れるスマホでは
ドロワーに残る）。SNSアイコンは、管理画面（トップページ）で URL を入れたものだけ出る。

### 3. KVを差し替える

`public/images/kv/hero.jpg` を置き、`src/content/event/*.md` の `hero:` に
パスを書く。指定が空のあいだは、構図確認用のグラデーションが表示される。

あわせて `heroStyle:` で見せ方を選ぶ。**KVにロゴやタイトルが描き込まれているかどうか**で決める。

| 値 | 見え方 | 向いているKV |
|---|---|---|
| `overlay` | 画像を全面に敷き、上にイベント名・日付を重ねる | 文字の入っていない写真 |
| `band` | 画像を切らずに丸ごと見せ、日付は下に置く | ロゴが絵の中に入っているイラスト |
| `split` | 左に情報・右にKV。切らずに1画面へまとめる | 同上。ヒーローを1かたまりに見せたいとき |

`overlay` でロゴ入りのKVを使うと、タイトルが二重になり絵も隠れる。
`band` は絵は守れるが、情報が下に置かれるぶん別ブロックに見えやすい。
`split` はその両方を避ける代わりに、横幅を情報とKVで分け合う。

`overlay` 以外では、KVをぼかした光を背面に敷いて情報とKVをつないでいる
（`.hero__glow`）。画像そのものを使うので、KVを差し替えれば色も追従する。

## コンテンツの入れ方

すべて `src/content/` 以下の Markdown。管理画面はこのファイルを
読み書きするだけで成立するよう、項目を最小限にしている。

### 地図

`mapEmbed` / `mapUrl` を書かなければ、`address`（なければ `venue`）で
Google マップを検索する形に自動で組み立てる。APIキーは要らない。
会場名を書くだけで地図が出るので、通常は何も設定しなくてよい。

片方だけ書いた場合は、そのURLの `q` / `query` から場所を取り出して
もう片方を組み立てる。管理画面に出す欄が1つで済むようにしてある。

### 来年の開催回

`src/content/event/` にもう1ファイル作る（`2027.md`）。`current: true` の
ものが優先で出る。無ければ `date` の新しい方。開催日の増減は管理画面から
できないようにしてあるので、日数が変わる年はここで組み直して渡す。

### 開催期間の表記

KVやチケットページの「2026.10.17 sat. - 10.18 sun.」は、`schedule` の各日の
`note` から組み立てる（`dateRangeLabel`）。同じ日付を2か所に書かなくてよい。

### PRムービー

`src/content/event/*.md` の `prVideo` に YouTube / Vimeo のURLを書くと、
トップページのABOUTと `/about/` に埋め込まれる。書かなければ何も出ない。

### `src/content/event/` — 開催回の基本情報（1開催 = 1ファイル）

日付・会場・タイムテーブル・チケット料金・注意事項・来場ゲストなど。
タイムテーブルは「部」の配列で持つ（DAY 1 / DAY 2 …）。
`items:` が空の部は「準備中です」と表示されるので、枠だけ先に置ける。
`current: true` の回がサイトの主役になる。翌年は `2026.md` を足して
前年の `current` を `false` にする。

### `src/content/items/` — カードで並ぶものすべて

`group:` に `src/config/site.ts` の `groups` のキー
（`movies` / `live` / `talk` / `foods` / `shops` / `stay`）を書くと、
その分類のセクションに出る。

```yaml
---
group: movies
title: "作品タイトル"
subtitle: "制作チーム名・監督名"   # タイトルの上に小さく出る
time: "17:30"                    # 開始時刻。時刻順に並ぶ
date: "10.17 SAT"                # 上映日。時刻と並べてカードの下に出る
image: /images/items/xxx.jpg
link: https://example.com        # 任意
featured: true                   # トップページのダイジェストに出す
draft: true                      # 下書き。本番ビルドには出ない
---
作品紹介（任意）。
```

カード1枚は「制作者名 → 作品タイトル → 紹介文の頭2行 → 上映日時」の順で並ぶ。
紹介文の続きは個別ページで読ませる。

### 作品ページに入れられるもの

```yaml
image: /images/items/xxx.jpg      # 一覧のサムネイル
video: https://youtu.be/xxxxxxx   # 予告編。YouTube / Vimeo
gallery:                          # 本文の下に並ぶサブ画像
  - /images/items/xxx-1.jpg
  - /images/items/xxx-2.jpg
runtime: "10 min"                 # 所要時間。日時の横に出る（ラベルは分類ごと）
```

**一覧のカードは必ず静止画、開いた先は動画があれば動画**になる。

| | カードのサムネイル | 開いた先の主役 |
|---|---|---|
| 動画も静止画もある | `image` | 動画 |
| 動画だけ | YouTubeのサムネイルを自動取得 | 動画 |
| 静止画だけ | `image` | `image` |
| どちらも無い | プレースホルダ | プレースホルダ |

動画リンクだけもらった作品でもカードに絵が出るので、
`image` は用意できるときだけでよい。
YouTubeの埋め込みは追跡の少ない `youtube-nocookie` に変換している。

並びは**一覧のカードと同じ**「映像 → 制作者 → タイトル → 日時 → 本文」。
カードから開いたときに写真とタイトルの上下が入れ替わらないようにしている。

### 個別ページとモーダル

`groups` で `detail: true` にした分類は、項目ごとに個別ページ
（`/<分類>/<ファイル名>/`）が作られる。

一覧やスケジュールから項目名を押したときは、**ページ遷移せずその場で
モーダル**が開く。モーダルは個別ページを取りに行き、`[data-detail]` の
中身だけを取り出して重ねている。URLも書き換わるので、そのままコピーすれば
その項目のリンクになり、戻るボタンで閉じられる。

新しいタブで開く操作、URLを直接叩いた場合、JSが動かない場合は、
普通のページとして開く。つまりモーダルは実ページの上に被せた層でしかなく、
壊れてもページ遷移に戻るだけで内容は失われない。
紹介文が長くなる分類は `src/config/site.ts` の `cardMin` を広げて
1枚あたりの幅を確保する（ムービーは 420px にして2列にしている）。

### `src/content/sponsors/` — 協賛ロゴ

`tier: 1`（大）〜`3`（小）で表示サイズが決まる。
`logo:` がなければ社名テキストで表示される。
ロゴ画像は黒背景に合わせて白抜きに変換して表示している
（`SponsorGrid.astro` の `filter`）。単色ロゴ前提なので、
多色ロゴを原色のまま出したい場合はここを外す。

## ページ内の切り替えについて

項目名のタイムテーブルでの書き方は、分類ごとに `scheduleFormat` で選ぶ。
`bracket` は「制作者「作品名」」（映画向け）、`plain` は名前だけ（出演者向け・既定）。

| 使う場面 | 使うもの |
|---|---|
| 開催日が2日以上 | `DayTabs`。全日を縦に並べ、上に現在地を示す目次を置く |
| 同じページ内の3セクション以上への移動 | `SubNav`。下線で現在地を示す目次 |
| 2セクション以下 | 何も置かない。そのまま下へ読ませる |

項目が2つだけだと、幅の広い帯にぽつんと浮いて弱く見える。
2つのときは目次を置かない。

目次も子メニューも囲み（ピル・カード）は使わない。押せる要素として
過剰に見えるうえ、どのサイトにもある既製品の見た目になるため。
現在地は下線とキーカラーで示す。

### スクロールで表示を差し替えない

`DayTabs` は**全日を常に表示する**。上のバーは押すとその日へスクロールし、
スクロール位置に応じて現在地がハイライトされるだけで、表示は入れ替わらない。

以前はスクロール量で日を切り替えていたが、**自分で動かしていないのに
画面が動く**ことになり落ち着かなかった。閾値やクールダウンを調整しても
この違和感は消えないので、仕組みごと持たないことにした。

日の区切りは、パネルの面（`--surface` / `--surface-2`）と大きな見出しで示す。

`DayTabs` はJSが動かない環境では全日が縦に並ぶので、内容は欠けない。
`/schedule/#day1` のようなURLで特定の日を開くこともできる。

## セクションの面（背景）について

トップページはセクションごとに面を交互に切り替えて、区切りを作っている。
`Section` の `surface` を付けると一段上の面（`--surface`）になり、
上下に細い罫線が入る。

ヒーロー（地）→ ABOUT（一段上）→ SCHEDULE（地）→ … の順で、
**隣り合うセクションが同じ面にならない**ことだけ守れば並びを変えてよい。
1か所だけ切り替えると、その隣が同じ面になって逆に境目が消えるので注意。

## 左右のマージンについて

セクションの幅は `.wrap`（最大 1080px・左右に `--page-pad`）に統一し、
**どのセクションも文字の始まる位置を揃える**。

本文やフォームのように1行が長くなると読みにくいものは、
`.wrap` の内側に `.measure`（最大 800px・左寄せ）を置いて行長だけ抑える。
`.measure` を中央寄せにすると、そのセクションだけ内側に入って見えるので使わない。

`--page-max` を広げすぎると、`.measure` との差が右側の空きとして目立ち、
大きな画面で全体が左に寄って見える。この2つは近い値に保つ。
`Section` コンポーネントの `narrow` はこの `.measure` を中身に付ける指定。

## 部品の分担

| 部品 | 役割 |
|---|---|
| `PageIndex` | ヘッダーの下に貼り付く目次バー。スケジュールの日切り替えにも、コンテンツの分類目次にも使う |
| `CardGrid` | 項目をカードで並べる。カード1枚に渡す値の組み立てはここに1本化 |
| `GroupSection` | 分類ひとつ分のセクション（見出し＋CardGrid） |
| `ItemMeta` | 日付・開始時刻・所要時間の1行。一覧でも個別ページでも同じ見え方にする |
| `ItemModal` | 個別ページをその場でモーダルとして開く層 |
| `DateText` | 日付の組み分け。曜日と年を小さく、月日を主役に |

同じ見た目のものを2か所に書かないこと。目次バーや日時の行のように
複数ページに出るものは、必ず部品にしてから使う。

### 部品に class を渡すときの注意

Astroのスコープ付きCSSは、その部品のテンプレートにある要素にしか効かない。
`<DateText class="hero__date" />` のように子へ class を渡しても、
親側で書いた `.hero__date { ... }` は当たらない。

級数や色を親から決めたいときは、**親側の要素で包んでから**中に置く。

```astro
<p class="hero__date">
  <DateText value={date} emphasis />
</p>
```

## 開発

```bash
npm install
npm run dev      # http://localhost:4340（.claude/launch.json 経由）
npm run build    # dist/ に静的書き出し
```

`draft: true` の項目は `npm run dev` では見えるが、`npm run build` では消える。
