# AREA UNITE / 汎用イベントサイト・テンプレート

スノーボード・アウトドア系のイベントサイトを想定した汎用テンプレート。
第1号の実装として AREA UNITE の内容を入れている。

**設計の前提**：このサイトはエリアユナイト専用のオリジナルデザインではなく、
**他のイベントにも使い回せるテンプレート**として作っている。
見出しやレイアウトに固有の癖をつけず、「見やすさ」と「差し替えやすさ」を優先する。

---

## 別のイベントに転用する手順

差し替えるのは次の3つだけ。ページやコンポーネントに手を入れる必要はない。

| # | ファイル | 変えるもの |
|---|---|---|
| 1 | `src/styles/theme.css` | ブランドカラー・背景・フォント・角丸（サイト全体の色が入れ替わる） |
| 2 | `src/config/site.ts` | イベント名・キャッチ・SNS・ナビ・一覧ページの種類（`groups`） |
| 3 | `public/images/kv/` + `src/content/` | KV画像と中身 |

### 1. 色を変える

`src/styles/theme.css` の `--brand` を変えるだけで、ボタン・見出しの罫・
時刻・リンクなど、アクセントが入るところがすべて追従する。
ライトテーマにしたい場合は `--bg` / `--surface` / `--text` を反転させる。

### 2. コンテンツの分類を増やす／減らす

グローバルナビは **ABOUT / TICKET / SCHEDULE / CONTENTS / ACCESS の5つに固定**し、
その下の分類は親ページの中のセクションとして持つ。ページを増やさずに項目を足せるので、
ナビが伸びていかない。

`src/config/site.ts` の `groups` に1件足すと、

- 親ページ（`/contents/` など）にセクションが1つ増える
- そのページ内タブに1つ増える
- グローバルナビの子メニュー（PCはホバー、スマホはドロワー）に1つ増える
- トップページ CONTENTS の導線カードに1枚増える

が全部まとめて起きる。減らすときは消すだけ。

```ts
workshop: {
  label: "Workshop",
  jp: "ワークショップ",
  lead: "当日開催する体験プログラム。",
  layout: "grid",       // grid = カード格子 / list = 時刻つきの1列
  ratio: "4 / 3",
  parent: "contents",   // contents か access
},
```

### スケジュールの持ち方

1日のプログラムは「部」のかたまり（`program`）の並びで持つ。
かたまりは、行を直接書くか、`include` で items コレクションの分類を丸ごと差し込む。

```yaml
program:
  - items:                     # 見出しなしの行
      - time: "12:00"
        title: ゲートオープン
  - part: 第2部 ／ ムービー     # 見出しつき
    include: movies            # items の movies を時刻順に差し込む
```

`include` を使うと、上映作品を CONTENTS ページとスケジュールで**二重に持たずに済む**。
作品や時刻を直すときは `src/content/items/` 側だけを直せば両方に反映される。
差し込まれた行は「制作者名」＋「作品名」の形で1行にまとめて表示する。
同じ時刻が続く行では、時刻は最初の1行にだけ出る。

SCHEDULE の子（DAY 1 / DAY 2 …）だけは設定ではなく開催回のデータから生える。
`src/content/event/*.md` の `schedule` に日を足すと、ページと子メニューが増える。
`time:` に `"12:00 - LATE"` のように書くとトップの要約に出る（省略時は
その日の最初と最後の時刻から自動で組み立てる）。

グローバルナビは、ヘッダー右のCTAボタンと同じ行き先の項目をバーから外す。
そのためチケットは「ボタン」としてだけ出る（CTAが隠れるスマホでは
ドロワーに残る）。SNSアイコンは `site.sns` に URL が入っているものだけ出る。

### 3. KVを差し替える

`public/images/kv/hero.jpg` を置き、`src/content/event/*.md` の `hero:` に
パスを書く。指定が空のあいだは、構図確認用のグラデーションが表示される。

あわせて `heroStyle:` で見せ方を選ぶ。**KVにロゴやタイトルが描き込まれているかどうか**で決める。

| 値 | 見え方 | 向いているKV |
|---|---|---|
| `overlay` | 画像を全面に敷き、上にイベント名・日付を重ねる | 文字の入っていない写真 |
| `band` | 画像を切らずに丸ごと見せ、日付は下に置く | ロゴが絵の中に入っているイラスト |
| `split` | 左に情報・右にKV。切らずに1画面へまとめる | 同上。ヒーローを1かたまりに見せたいとき |

`overlay` でロゴ入りのKVを使うと、タイトルが二重になり絵も隠れる。
`band` は絵は守れるが、情報が下に置かれるぶん別ブロックに見えやすい。
`split` はその両方を避ける代わりに、横幅を情報とKVで分け合う。

`overlay` 以外では、KVをぼかした光を背面に敷いて情報とKVをつないでいる
（`.hero__glow`）。画像そのものを使うので、KVを差し替えれば色も追従する。

## コンテンツの入れ方

すべて `src/content/` 以下の Markdown。将来の管理画面はこのファイルを
読み書きするだけで成立するよう、項目を最小限にしている。

### `src/content/event/` — 開催回の基本情報（1開催 = 1ファイル）

日付・会場・タイムテーブル・チケット料金・注意事項・来場ゲストなど。
タイムテーブルは「部」の配列で持つ（DAY 1 / DAY 2 …）。
`items:` が空の部は「準備中です」と表示されるので、枠だけ先に置ける。
`current: true` の回がサイトの主役になる。翌年は `2026.md` を足して
前年の `current` を `false` にする。

### `src/content/items/` — カードで並ぶものすべて

`group:` に `src/config/site.ts` の `groups` のキー
（`movies` / `live` / `talk` / `foods` / `shops` / `stay`）を書くと、
その分類のセクションに出る。

```yaml
---
group: movies
title: "作品タイトル"
subtitle: "制作・監督名"      # タイトルの上に小さく出る
time: "17:30"                # あると時刻順に並び、サムネイルに時刻が乗る
image: /images/items/xxx.jpg
link: https://example.com    # 任意
featured: true               # トップページのダイジェストに出す
draft: true                  # 下書き。本番ビルドには出ない
---
本文（任意）。
```

### `src/content/sponsors/` — 協賛ロゴ

`tier: 1`（大）〜`3`（小）で表示サイズが決まる。
`logo:` がなければ社名テキストで表示される。
ロゴ画像は黒背景に合わせて白抜きに変換して表示している
（`SponsorGrid.astro` の `filter`）。単色ロゴ前提なので、
多色ロゴを原色のまま出したい場合はここを外す。

## 左右のマージンについて

セクションの幅は `.wrap`（最大 1180px・左右に `--page-pad`）に統一し、
**どのセクションも文字の始まる位置を揃える**。

本文やフォームのように1行が長くなると読みにくいものは、
`.wrap` の内側に `.measure`（最大 820px・左寄せ）を置いて行長だけ抑える。
`.measure` を中央寄せにすると、そのセクションだけ内側に入って見えるので使わない。
`Section` コンポーネントの `narrow` はこの `.measure` を中身に付ける指定。

## 開発

```bash
npm install
npm run dev      # http://localhost:4340（.claude/launch.json 経由）
npm run build    # dist/ に静的書き出し
```

`draft: true` の項目は `npm run dev` では見えるが、`npm run build` では消える。
